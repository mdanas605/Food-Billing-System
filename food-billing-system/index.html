Object-Oriented Programming (OOP) Architecture

Detailed explanation of the 6 core OOP concepts implemented in this application for your college viva/demo.

Concept 1

Class & Object

A Class is a blueprint or template, while an Object is a concrete runtime instance. 

// Class Definition
class FoodItem {
    constructor(id, name, price) {
        this.name = name;
        this.price = price;
    }
}

// Object Instantiation
const burger = new VegItem("B01", "Burger", 120);
Used in FoodEase: FoodItem, Cart, CartItem, Customer, Billing, Order.
Concept 2

Encapsulation (Private Fields)

Bundling data and methods together while hiding internal state using JavaScript private fields (#fieldName) and public getters/setters. 

class Billing {
    #gstRate; // Private field (hidden)

    constructor(gstRate = 5) {
        this.#gstRate = gstRate;
    }

    getGSTRate() { return this.#gstRate; }
    setGSTRate(rate) { /* bounds validation */ }
}
Used in FoodEase: #gstRate, #discountRate in Billing; #items in Cart; #phone in Customer.
Concept 3

Inheritance (extends & super)

Child classes inherit properties and methods from parent classes, avoiding code duplication and establishing "is-a" hierarchies. 

class VegItem extends FoodItem {
    constructor(id, name, cat, price, desc, img) {
        super(id, name, cat, price, desc, 'veg', img);
        this.dietaryTag = "100% Veg";
    }
}
Used in FoodEase: VegItem & NonVegItem inherit from FoodItem; DineInOrder, TakeawayOrder, and DeliveryOrder inherit from Order.
Concept 4

Polymorphism (Method Overriding)

The same method name behaves differently depending on the class of object calling it. 

// Overridden in VegItem
getBadgeHTML() {
    return '<span class="veg-badge">Pure Veg</span>';
}

// Overridden in NonVegItem
getBadgeHTML() {
    return '<span class="nonveg-badge">Non-Veg</span>';
}
Used in FoodEase: getBadgeHTML() and getTypeDetails() in FoodItem subclasses; getOrderTypeBadge() in Order subclasses.
Concept 5

Abstraction

Hiding complex background arithmetic, tax calculations, and validation rules behind intuitive public interfaces. 

// Caller simply invokes one clean method:
const breakdown = billing.calculateBreakdown(subtotal, discount);
// Caller receives clean totals without knowing
// internal CGST/SGST splitting algorithms
Used in FoodEase: Billing.calculateBreakdown(), Customer.validate().
Concept 6

Factory Method Pattern

A creational OOP design pattern that provides an interface for creating objects without specifying the exact class of object created. 

static createOrder(data) {
    if (data.orderType === 'dine-in')
        return new DineInOrder(...);
    if (data.orderType === 'delivery')
        return new DeliveryOrder(...);
    return new TakeawayOrder(...);
}
Used in FoodEase: Order.createOrder() accurately instantiates polymorphic subclasses from raw localStorage objects.
